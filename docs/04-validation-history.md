# 04 · 实机验证历史

> 所有数据来自同一台机器（MRID6-23，BIOS V38，EC 0.38）。
> 没有独立电气测量，速率/容量均来自电池接口报告。

---

## 阶段 0 · 只读语义门（2026-10-07）

第一次实机接触**只读**，读了 20 个审计地址，12 项语义检查全过：

```
ec_version_accepted             [0, 38, 0, 0]
platform_is_mrid6               MECHREVO / Jiaolong Series MRID6 / MRId6-23 / BIOS MRID6_23_R_V38
mailbox_idle                    0x8150 = 0x00
mode_known                      0x83C0 = 0x00
ac_consistent                   EC=True  Windows=True
soc_consistent                  EC=100%  Windows=100%  delta=0
battery_present                 EC=True  Windows=True
registers_stable                多轮扫描逐位一致
```

关键收获：`0x8411 = 0x26 = 38`，**EC 内部版本与 SMBIOS 报告一致**，
扩展 `0x92` 读协议在 0.38 上工作正常。

|---|---|---|---|

| `8152` | `00` | `55` | `55` |

### ⚠️ 这次的教训

第一次判据要求**立即**满足 `requested_current_zero`，于是判失败并 poison —— **假阴性**。
实际上 `0x0E` 生效了，只是 `8370` / `837C` 还没沉降。

→ 促成了"硬判据 + 沉降轮询"的改造。

### 稳定性（51 秒，6 次采样）

```
14:29:48 ~ 14:30:39
EC SOC       : 79 79 79 79 79 79     ← 冻结
Windows SOC  : 76 76 76 76 76 76     ← 冻结（不同来源）
ChargeRate   : 0  0  0  0  0  0
DischargeRate: 0  0  0  0  0  0
RemainingCapacity: 39140 ×6          ← 冻结
Voltage      : 15400 ×6              ← 恒定 → 确实没有电流
```

**结论：插电、不充、不放，电池静置，电脑吃适配器。**

### ⚠️ 又一次假阴性

验收判据里有 `charging_false_windows` 和 `charge_rate_zero`，
但 Windows 电池类驱动的上报**滞后数分钟**，于是自动判据报 `pass: false`。
EC 侧和 CIM 独立遥测都已确认 `charging=false` / `rate=0`。

→ 教训：**Windows 上报应作为"最终一致"而非"即时一致"来判**。

## 阶段 4 · 过夜漂移（2026-10-07 夜 → 10-08 早）

用户报告：晚上 76% → 凌晨 83% → 早上 82%。

### 排查结果

| 项目 | 结果 |
|---|---|
| 系统重启？ | 14:48 有过一次**用户主动重启**（Windows Update 前后） |
| 配置丢了吗？ | ❌ **没丢**：`83C0=0x48`、`83A1/83A2=80/60` 全部活着 |
| 现在在充电？ | ❌ 没有：`charging=false`、`ChargeRate=0`、电压恒定 15400 mV |
| 剩余容量 | 39140 → 41290 mAh（+2150） |

### 解释（诚实版）

**能确认的**：模式活着、阈值正确、此刻在停充、没有放电。

**不能 100% 断定的**：那 +2150 mAh 是"短暂充了电"还是"电量计重算"。
两者都符合观测。判断依据：

- 若真充电，按 30 W 只需 4–5 分钟 —— 可能发生在重启前后的电源转换窗口
- 电量计在停充静置后重算剩余容量，也是涨跌都可能

**但有一点明确**：它停在 83%，**不是 100%**，且此刻充电是停的。
对照启用前"插电过夜必到 100% 并长期满电"，养护功能是生效的。

### 为什么精度只有 ±3%

EC 判停用的是它自己的 SOC（`0x847C`），这个值本身会漂。
**上限精度取决于电量计精度**，这从 Windows 侧无法修正。

真实实测量化：**实测停在 76%–83% 区间**，而非精确 80%。

## 阶段 5 · 硬断电后丢失（2026-10-07 之后）

用户清灰 + 拔电 + **长按电源键**。

长按电源键是**强制断电**，EC 被硬件复位。

### 结果

```
83C0 = 0x00      ← 模式回到正常
83A0 = 0x00      ← 无原生子状态
83A1/83A2 = 00/00 ← 阈值清空
```

充电恢复原厂行为：`charging=true`、`ChargeRate ≈ 28.7 W`、SOC 一路涨。

### 重要结论

| 场景 | 配置是否保留 |
|---|---|
| 正常重启（Windows reboot） | ✅ 保留（实测过一次） |
| **硬断电 / 长按电源键** | ❌ **丢失**，需重新配置 |
| 睡眠 / 休眠 | ⚠️ 未系统验证 |

**所以：不要为了"快点关机"去长按电源键。** 正常关机不会丢。

## 数据可信度说明

- 寄存器值来自 EC XRAM 实读，有多次一致性采样
- 充/放电速率、剩余容量来自 Windows `BatteryStatus`（ACPI 上报值）
- **没有独立电气测量**（没有万用表/钳表）
- 已知 `0x847C`（EC SOC）与 Windows 百分比是两个不同来源，差 1–7 点属正常
