# 02 · 固件分析：为什么 EC 0.38 可以用这套命令

## 问题

手头能拿到的 EC 固件镜像只有 **0.35** 和 **0.40**，而本机跑的是 **0.38**。

那凭什么认为 0.38 的行为和 0.40 一致？

---

## 结论先行

对 `ec_35.bin` 与 `ec_40.bin` 做逐字节比对：

- 各 **131073** 字节（文件尾部多 1 个 `0xFF`）
- **只差 15 个字节**
- 这 15 个字节**全部**落在版本/日期字符串和一张参数表
- **19 个充电控制寄存器访问点，0/19 落在差异区**

因此：**这套命令的代码在 0.35 与 0.40 之间完全一致**。
0.38 位于两者之间，同样的代码区域极大概率也一致 —— 而且这一点随后被**实机验证**确认了。

---

## 差异明细

15 个差异字节分布在 9 段：

| 偏移 | 0.35 | 0.40 | 性质 |
|---|---|---|---|
| `0x0004A–0x0004B` | `f1 53` | `d0 de` | 校验/签名相关 |
| `0x071B7–0x071B8` | `3a 3a` | `35 35` | 参数表 |
| `0x071F3–0x071F4` | `3a 3a` | `35 35` | 参数表 |
| `0x0722F–0x07230` | `3a 3a` | `35 35` | 参数表 |
| `0x0726B–0x0726C` | `3a 3a` | `35 35` | 参数表 |
| `0x08036` | `33` | `38` | 版本数字 |
| `0x08040` | `23` | `28` | 版本串 `00.23` → `00.28` |
| `0x0804F` | `31` | `38` | 日期 `2024/01/10` → `2024/08/02` |
| `0x08051–0x08052` | `31 30` | `30 32` | 日期 |

> 注意版本编码：固件内部串是 `00.23.00.00` / `00.28.00.00`，
> 而 SMBIOS 报的是 **0.35 / 0.40**。两套编号不同，别对错。
> 实机读 `0x8411` 得到 `0x26` = **38**，与 SMBIOS 的 0.38 一致。

## 逐字节相同的区域（充电控制代码全在这里）

| 区域 | 内容 |
|---|---|
| `0x00700–0x00800` | Keil switch helper（`7A4A`） |
| `0x00900–0x00A80` | 主机命令分派表：`80/81/82/83/84/92/93/DC/F0` |
| `0x02F00–0x03000` | 控制检查 |
| `0x03E00–0x03F40` | **原生阈值状态机 + 调度器** |
| `0x04400–0x04500` | 请求电流清零（`4473`） |
| `0x04500–0x04700` | **原生阈值参数拷贝 + 邮箱处理** |
| `0x04A00–0x04C00` | 邮箱事务处理（`8150` 轮询） |

复现方法见本文件末尾。分析用的原始镜像不随仓库发布（见 [`SAFETY.md`](../SAFETY.md#-为什么仓库里没有驱动文件)）。

## 怎么复现这套分析

### 1. 拿到镜像

- EC 镜像完整包含在 BIOS 镜像 **偏移 `0x81000`** 起的 131073 字节
- 也就是说：有 BIOS 镜像就等于有 EC 镜像
- 镜像尾部多 1 字节 `0xFF`

### 2. 校验

```python
import hashlib
data = open('ec.bin','rb').read()
assert len(data) == 131073
print(hashlib.sha256(data).hexdigest())
```

已知哈希：

```
ec_35.bin  007756ae54e7f6a29aedec4447846d53759ed9f7c94be0b0964afc0f6bea8c70
ec_40.bin  7573b2cb494e9a308e2ab13bf5fcb5f90d0d111922e6cfe41487219159993430
```

### 3. 逐字节比对

```python
a = open('ec_35.bin','rb').read()
b = open('ec_40.bin','rb').read()
diffs = [i for i in range(len(a)) if a[i] != b[i]]
print(len(diffs), [hex(i) for i in diffs])
```

应该看到 **15** 个。

### 4. 8051 指令定位

搜索 `MOV DPTR,#imm16` 的字节序列 `90 hi lo`：

```python
import re
def find_dptr(code, addr):
    pat = bytes([0x90, (addr >> 8) & 0xFF, addr & 0xFF])
    return [m.start() for m in re.finditer(re.escape(pat), code)]
```

## 一个反直觉的坑

**在二进制里搜地址字符串是找不到的。**

`0x8150` 不是以 ASCII `"8150"` 存在，而是作为指令立即数 `90 81 50` 存在。
同理，设备名、驱动名是 **UTF-16** 存的，用 ASCII 搜会全部落空
（本项目就在这上面浪费过时间，见 `docs/03-transport-design.md`）。

---

## 静态分析不能替代实机验证

静态证明的是"**代码没变**"，不是"**行为一定对**"。

所以本项目的做法是：静态证明 + **实机只读语义门**（逐项核对寄存器组合是否自洽）
+ 分阶段写入验证（先 `0x0E` 停充、再 `0x0F` 恢复、最后才 `0x0D`）。
