## 两个地址空间，别搞混

这是本项目最容易踩的坑：

```
CPU 代码地址  vs  EC XRAM 地址  vs  PC I/O 端口
```

- **PC I/O 端口** `0x62` / `0x66` —— CPU 访问 EC 的窗口（ACPI 标准）
- **EC XRAM** `0x8150` 等 —— EC 内部 RAM，**不是** PC 端口
- **CPU 代码地址** `0x8150` —— 那是 EC 固件里的代码位置，和 XRAM `0x8150` **完全无关**

> IT5570 的 XRAM `0x8000–0x97FF` 与它的"低位别名"要分开看。

---

## 为什么标准 ACPI EC 命令到不了 0x8150

标准 ACPI EC 用命令 `0x80`（读）/ `0x81`（写），偏移是 **8 位**，映射到 `0x8400 + offset`。

所以：

```
写 ECF2 偏移 0x50  →  落到 XRAM 0x8450，不是 0x8150 ❌
```

**必须用固件实现的扩展命令**才能访问 `0x8150`：

```
读 (0x92): OUT 0x66,0x92 → OUT 0x62,地址高 → OUT 0x62,地址低 → 等 OBF → IN 0x62
写 (0x93): OUT 0x66,0x93 → OUT 0x62,地址高 → OUT 0x62,地址低 → OUT 0x62,数据 → 等 IBF 清
```

**顺序是先高字节后低字节**（经过离线逐字节执行验证）。

## DSDT 映射表（EC XRAM ↔ 主机物理地址）

`OperationRegion(ECF2, SystemMemory, 0xFE800400, 0xFF)`

| 字段 | ECF2 偏移 | 主机物理地址 | EC XRAM |
|---|---|---|---|
| 版本 | 10–13 | `FE800410–13` | `8410–8413` |
| `ECWR` 电源/电池状态 | 60 | `FE800460` | `8460` |
| 设计容量（16 位） | 64 | `FE800464` | `8464` |
| 满充容量（16 位） | 68 | `FE800468` | `8468` |
| 报告速率（16 位） | 6C | `FE80046C` | `846C` |
| 剩余容量（16 位） | 6E | `FE80046E` | `846E` |
| SOC% | 7C | `FE80047C` | `847C` |
| `BTCM` | 91 bit5 | `FE800491` | `8491` |
| `BATM/BBHL/BBLP/BBHM` | 96–99 | `FE800496–99` | `8496–8499` |

**重要**：`846C` 是"报告给 ACPI 的速率"，`837C/837D` 是固件内部的"请求充电电流缓冲"。
**两者都不是实测电流。**

`8460`（`ECWR`）位定义：

| bit | 含义 |
|---|---|
| 0 | 适配器在位 |
| 1 | 电池在位 |
| 2 | 充电中 |
| 3 | 放电中 |
| 4 | 电量临界 |

`_BST` 就是由这些位拼出来的。

## 充电控制相关寄存器（本项目用到的）

### 邮箱

| XRAM | 含义 | 说明 |
|---|---|---|
| `0x8150` | 主命令 | `0` = 空闲；`0x10` = 电池组命令 |
| `0x8151` | 子命令 | `0x0D` 原生阈值 / `0x0E` 停充 / `0x0F` 恢复 / `0x0C` **主动放电** |
| `0x8152` | 结果 | `0x55` = 处理函数返回。**不等于子命令生效** |
| `0x8153` | 原生阈值上限 | 80 → `0x50` |
| `0x8154` | 原生阈值下限 | 60 → `0x3C` |

**提交顺序**：参数先 → 子命令 → 主命令 `0x10` 最后。

### 状态

| XRAM | 含义 | 取值 |
|---|---|---|
| `0x83C0` | 模式位 | `0x00` 正常 / `0x02` 停充 / `0x48` 原生阈值 |
| `0x8370` | 调度状态 | `0x04` 正常插电 / `0x31` 停充 / `0x32` 原生保持 / `0x10` 满电空闲 |
| `0x83A0` | 原生子状态 | `1` 初始化（**可能放电**） / `2` 停充保持 / `3` 允许充电 |
| `0x83A1` | 上限副本 | 来自 `0x8153` |
| `0x83A2` | 下限副本 | 来自 `0x8154` |
| `0x837C/0x837D` | 请求充电电流缓冲 | 16 位，小端 |
| `0x8394/0x8395` | 辅助状态 | 停充时变化 |
| `0x8410–0x8413` | EC 版本字节 | 0.38 → `00 26 00 00` |
| `0x847C` | **EC 自己的 SOC** | 0–100 |

### 模式位 `0x83C0` 的语义

| 子命令 | 位变化 | 状态机 |
|---|---|---|
| `10/0C` | `83C0 \|= 0x01` | `8370=30` → `4054` → `3DF1` → `2DE2(R7=1)` = **主动放电** |
| `10/0E` | `83C0 \|= 0x02` | `8370=31` → `4057` → `3D90` → `2DE2(R7=0)`、`3025` = **停充** |
| `10/0D` | `83C0 \|= 0x48`；参数 → `83A1/83A2` | `8370=32` → `405A` → `3E09` = **原生阈值** |
| `10/0F` | 清 `83C0` 的 `01/02/08/20/40` | 回原厂策略 |

`3025` 会调 `4473` 把 `837C/837D` 清零，再调 `2F68` 写充电器（可追到 SMBus 命令 `0x14`）。

## 原生阈值状态机（`0x0D`）

| 子状态 `83A0` | 条件 | 行为 |
|---|---|---|
| `1` 初始化 | SOC > 上限 | **调用 `2DE2(R7=1)` = 主动放电** |
| `1` 初始化 | SOC ≤ 上限 | 转入子状态 2 |
| `2` 保持 | SOC ≥ 下限 | 停充 + 请求电流清零 |
| `2` 保持 | SOC < 下限 | 转入子状态 3 |
| `3` 允许充电 | SOC < 上限 | 恢复电池请求充电参数 |
| `3` 允许充电 | SOC ≥ 上限 | 转回子状态 2 |

**这就是为什么必须 SOC < 80% 才启用**：否则命中第一行。

## 已排除的通道（别再试）

| 路径 | 结论 |
|---|---|
| Windows / ACPI / WMI 原生阈值接口 | ❌ 没有 |
| 厂商控制中心 | ❌ 374 个文件里无充电阈值相关，二进制里只有 `\\.\PhysicalDrive` 和 `\\.\pipe`，无 EC 通道 |
| `\\.\ACPIDriver`（Uniwill H2RAM） | ❌ `CreateFileW` → 错误 2，不存在 |
| `AcpiTest_MULong`（AMI WMI） | ❌ 本机是 Insyde BIOS，无此设备 |
| Bitland `MIFS`（`MICommonInterface`） | ⚠️ 通道存在，但函数表只有性能/风扇/RGB/灯效，**无电池命令**，且是固件 RPC、无地址字段 |
| Uniwill 那套 `0x07B9/0x07C3/0x087F` | ❌ 不同 EC，不适用 |
| DSDT 里的 `_BMC/_BMD` | ❌ 不存在；`BTCM/BATM/BBHL/BBLP/BBHM` 只有定义没有设置方法 |

> `_BTP` 是容量变化通知门限，**不是**充电上限。
